## Context

The 2026-09-11 Roppongi session (archived at `build/traces/2026-09-11-roppongi-{trace,textout}.bin`) proved overlay v6 served nothing wrong. What remains was found by an inspection pass and an adversarial pass:

- 145 of 192 Japanese draws are six spans whose English is written across a branch target (the cap works; the table row is authored across a jump).
- The verifier's 165 findings were false: `trace.S` picks the record to hash from the stale engine global `RECID` (`giten/exe/trace.S:137`) while `hook.c` finds it from the pc (`find_record`, `hook.c:208-228`).
- "Maccカ" is an exe-patcher bug: five strings are loaded piecewise (dword+word+byte) and `menus.py` repoints only the dword.
- Three shipped hazards: 24 spans served from partially tiled records whose branch targets are not all known; duplicate record ids resolve **last**-wins in the engine while every model copy says first; the overlay ignores the byte builder's `blocked` refusals.
- Four blank rows; five untranslated exe strings (the Mood field); tool defects in `screen_audit.py`; the install's `et/ET0004.BIN`/`ET0101.BIN` are not reproducible from the tree.

**On "why can't we tile everything":** we can. The engine is the tiler: the dev build logs every token dispatch, so running a record once gives its exact boundaries, and every untiled record in the corpus is untiled only because the engine was never made to run it while recording. Item 3d makes the "untiled" category disappear: every record ends up tiled by observation or proven data. For the reachable residue in particular: The census (`script.parse` over every `m/`+`et/ID` file) leaves, outside the five files with no loader (`MS610D`, `MS6200`, `MS6500`, `MS6F00`, `MS6F1F`), exactly this:

| record | state | error | what settles it |
|---|---|---|---|
| `m/MS0031` c0 r00 | untiled | switch entry at 0x61 has kind 13: the walk desynced upstream | the engine's own token boundaries |
| `m/MS0031` c0 r0B | untiled | unterminated `pairs_ff` at 0x23A (the corpus's only one) | same; may prove the record is dead data |
| `m/MS0031` c0 r02, r03, r0D, r17 | straddle-tiled | last token reads 1–3 bytes into the next record | tokens are already known; only the overlay policy treated them as untiled |
| `m/MS0080` c0 r00–r04 | prefix-tiled | head `1f 00 02 1f 00 01 1f ff 00` is read as pool calls and resyncs by luck; trailer `1f 00 10 01 01 00` | the engine's own token boundaries |

Nothing was ever finished because **no trace has ever reached these records**: the Roppongi trace has zero events whose record content matches any of them, and neither do the nine earlier sessions. The tool to reach them exists: `tools/make_warp.py` builds a JP tree whose opening jumps straight to any `m/MS00xx` record, and `partial.observed_boundaries` turns the resulting trace into the engine's own tiling. That is a five-minute play per warp. Item 3 below therefore *finishes* the tiles instead of only refusing them; the strict rule (serve a container only when every branch target in it is known) is adopted, and the warp step is what makes it cost nothing reachable.
